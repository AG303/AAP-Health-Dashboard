How the dashboards are built

Two independent scripts run every evening with read-only tokens. aap_health_dashboard.py uses only the AAP APIs (platform gateway, automation controller, Event-Driven Ansible, automation hub). ocp_health_dashboard.py uses only the OpenShift API and cluster monitoring (AAP namespace, operator, storage, backups, routes, nodes, etcd, alerts). Each has its own score, history and pages.

aap_health_dashboard.py / ocp_health_dashboard.py v2.0.0. Read-only: every call is an HTTP GET with a read-only token. Hostnames and URLs are redacted.

Hours saved is an estimate: successful jobs x 15 minutes. Health checks follow Red Hat guidance: AAP 2.6 - Planning your cluster (ping, heartbeats, instances) · AAP 2.6 - Ensure system health through monitoring (metrics of interest) · AAP 2.6 - Send metrics to system monitoring software · AAP 2.6 - Platform gateway OpenAPI (/api/gateway/v1/status/) · AAP 2.6 - EDA API root (status, activations, instances) · AAP 2.6 - Operator growth topology (operator database limits) · AAP 2.6 - Performance considerations for operator environments · AAP 2.6 - Back up the platform on OpenShift · AAP 2.6 - AnsibleAutomationPlatform custom resource · Red Hat AAP life cycle · Red Hat - OpenShift 4 cluster health pre-checks · OpenShift 4.20 - Validation and troubleshooting · OpenShift 4.22 - Working with nodes (node conditions) · OpenShift 4.18 - Recommended performance practices (etcd) · OpenShift cluster-etcd-operator - etcd performance metrics
